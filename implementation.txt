## Change made

`crates/playback/src/pipeline.rs` now constructs and validates a replacement
stream before retiring the current decode epoch. Failed replacement no longer
leaves a dead ring source in the sink. Seek rebuilds call the decoder's real
`try_seek` before filling the new ring; the frame counter remains seeded to the
requested position.

## Follow-up closure record

The pre-fix failure was a transaction-ordering bug in
`crates/playback/src/pipeline.rs`: the active decode epoch was shut down before
the replacement had opened and completed its seek. A failed replacement then
left the sink consuming a dead ring. The old seek path also changed only the
frame counter. The fixed path waits for a decode-worker readiness handshake,
calls `try_seek`, commits the replacement, and only then shuts down the old
epoch. Focused tests are named `failed_rebuild_does_not_tear_down_current_stream`,
`successful_rebuild_replaces_current_stream`, and
`decoder_seek_moves_decoder_not_only_position_counter`.

Debug-only live logs captured redacted HTTP `206` range status, requested byte
ranges, response byte counts, AAC/progressive-MP4 metadata, future expiry
metadata, and decoder readiness at `seek_ms=30000`. The final no-synthetic run
kept a real stream active while repeated catalogue searches ran for 126
seconds; its final captured window had `stream_errors=0` and 17,218,643 reads.
No signed query strings were recorded. A clean five-minute soak was not run.

The debug E2E driver previously generated a synthetic sine WAV for its local
queue branch. That violated the real-media invariant, so the generator and its
temporary output were removed. The driver now uses only an already indexed
owner-provided local file and reports `NOT RUN` when none exists. Existing fake
providers and audio fixtures are confined to unit/parser tests.

The remaining evidence limitations are explicit in `reports.txt`: no physical
audibility, no complete seek matrix, no ten-run first-audio distribution, no
expiry-boundary pause, and no complete live queue/relaunch/offline/error-kind
matrix.

## 2026-11-04 Part A — Settings crash (query-key collision)

Root cause: React Query key collision between `shell/Toolbar.tsx` (added in the
UI pass) and `pages/SettingsPage.tsx`. Toolbar called `sources_get` — whose
rows have no `health` — under the key `['sources']`, the same key Settings uses
for `sources_get_with_health`. Whichever query landed first wrote the cache;
when Toolbar won, Settings mapped health-less rows and `health.state` threw.

- `shell/Toolbar.tsx`: source query key is now `['sources', 'config']`.
- `pages/SettingsPage.tsx`: `health` is treated as optional on the wire
  (`healthState = health?.state ?? null`), rendering the base URL for ok, the
  reason for unreachable/rejected, and an honest "Status unavailable" otherwise.
- `pages/SettingsPage.tsx`: each of the six sections is wrapped in the EXISTING
  `AppError` boundary in a new inline mode, so one broken section shows
  "This section couldn't load" + Retry instead of blanking the route.
- `shell/AppError.tsx`: additive `inline` prop (full-screen fallback unchanged).

No Rust, IPC, CSP, allowlist, queue/resolver or player logic touched.
